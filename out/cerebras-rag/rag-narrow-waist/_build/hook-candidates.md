# hook 候選：Cerebras RAG 第 1 則（`rag-narrow-waist` ＋ `slack-distillation-and-bursting`）

這一則的內容範圍：窄腰心智模型、embeddings table 只有五個欄位、connector 只回答三個問題、
「形式統一但語意分裂」的陷阱、distillation（寫入前先讓 LLM 正規化成四樣）、bursting 與三道品質門檻、
寫入時過濾比 rerank 便宜。背景（每天 15,000 次查詢、資料橫跨 Slack／Wiki／程式碼／Jira）只在這一則完整講。

**相鄰樣態限制**：上一則發布的是 Claude Code 第 2 則（並列式），所以這一則不用並列式。
排序照人的偏好：疑問式在前，反差式／取捨式在後。

未定案。人挑定後才寫進 `series/cerebras-rag/series.md` 的 `planned_title` 與 spec 的 `hook`。

## A（讀者疑問）

- 主標：`Slack、Wiki、程式碼、Jira，`／`怎麼塞進[[同一張表]]？`
- 副標：`Cerebras 的內部搜尋每天被問 15,000 次。`／`它的答案是：這張表只留五個欄位。`
- 沒看過系列的人看到會懂：一間公司有四種亂七八糟的資料，要讓人搜得到，他們把格式統一成一張很窄的表。
- 引用：`c3`（15,000 次／四種來源，官方宣稱）、`c4`（五個欄位）
- 風險：無。範圍、主詞都在字面上。

## B（讀者疑問）

- 主標：`一條 Slack 吵了 50 則，`／`怎麼變成[[搜得到的答案]]？`
- 副標：`先讓 AI 讀完整條討論串，抽成四樣固定格式，`／`再存進搜尋用的資料庫。`
- 沒看過系列的人看到會懂：公司內部的對話很亂，他們先用 AI 整理成固定格式才存起來，這樣才搜得到。
- 引用：`slack-distillation-and-bursting:c6`（10 個人吵了 50 則，部落格舉例）、`:c3`（四樣結構化資料）
- 風險：「50 則」是文章自己舉的例子，不是統計數字；內文要標「假設的例子」。

## C（情境痛點）

- 主標：`每多接一種資料，`／`就要改一次搜尋邏輯？`
- 副標：`Cerebras 把中間的介面收到只剩五個欄位，`／`新增來源只要交一個小程式，核心系統一行都不用改。`
- 沒看過系列的人看到會懂：接新資料很麻煩，他們靠「把介面做窄」讓新增資料變成別的團隊自己就能做的事。
- 引用：`c4`、`c5`（新增來源讀取端不用改）、`c10`（開一個 PR、附一個小型 Python module）
- 風險：無。「一行都不用改」是卡上原文「完全不用改一行」。

## D（反直覺斷言）

- 主標：`原始對話[[不進]]向量庫，`／`先交給 AI 重寫一遍`
- 副標：`文章用的詞是「正規化」不是「摘要」——`／`重點是讓每筆資料長得一樣，不是弄短。`
- 沒看過系列的人看到會懂：他們不把原文直接拿去做 AI 搜尋，而是先統一格式；統一格式本身就是關鍵。
- 引用：`slack-distillation-and-bursting:c3`、`:c4`（原文另外走全文索引）、`:c8`（normalized 不是 summarized）
- 風險：副標提到「正規化」這個詞，要在內文第一次出現時就用白話講清楚。

## E（代價與取捨）

- 主標：`只留五個欄位，`／`其他全部[[當成一包不透明的 JSON]]`
- 副標：`好處是寫入端和讀取端可以各改各的、互不干擾；`／`代價是排序要用到的資訊，得在第一天就想好。`
- 沒看過系列的人看到會懂：統一格式有好處也有代價，代價是事後要補資訊很貴。
- 引用：`c4`、`c1`（各自獨立演化）、`c12`（事後想加要把整個 corpus 重新處理一次）
- 風險：主標偏長也偏技術（JSON）；一般讀者可能卡在 JSON 這個詞。

## F（代價與取捨，聚焦門檻）

- 主標：`哪句閒聊值得被記住？`／`他們設了[[三道門檻]]`
- 副標：`要有罕見的詞、至少 200 個字、有人按過表情符號。`／`沒過的那些，連存都不存。`
- 沒看過系列的人看到會懂：不是所有訊息都值得進知識庫，他們用三個很具體的規則先篩掉一批。
- 引用：`slack-distillation-and-bursting:c10`（IDF ≥ 4.0、長度 ≥ 200 字元、有 reaction 加分）、`:c12`（寫入時過濾比 rerank 便宜）
- 風險：「200 個字」卡上寫的是「200 字元」，主標要照卡寫成「200 個字元」或改寫；
  而且這是整則裡比較小的一塊，封面指向它，讀者對「四種資料怎麼統一」的期待會落空。
