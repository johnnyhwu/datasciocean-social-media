```text
搜尋每次都把所有工具叫一遍？又慢又貴

假設你問公司的知識庫「部署失敗，上次怎麼修的？」。Cerebras 的做法是先讓一個模型（planner）決定這次該用哪幾個工具，例如搜 Slack、搜程式碼。它只做分類、不寫答案，所以可以用小模型，故意設計得比它服務的工具還便宜；選好的工具彼此沒有依賴，同時去查。

查回來的證據原封不動，留到最後寫答案那一步（synthesis）一次讀完；工具只交原始資料，不推理、不摘要。這條原則 Cerebras 沒有直接講，是從它的設計推出來的。換成每一路先各自摘要再合併，跨來源的答案拼不起來，細節也會在兩次壓縮裡不見。例外是 SQL 這種要當場算的查詢，那次推理留著、藏進工具內部。

整條流程決策一次、查一次、答一次就結束，沒有回頭再查的迴圈。Cerebras 沒有這樣替自己分類，但照這個結構，它是單輪流程：用了 LLM 做決策，不等於 agentic。

這是系列第 3 則。
```
