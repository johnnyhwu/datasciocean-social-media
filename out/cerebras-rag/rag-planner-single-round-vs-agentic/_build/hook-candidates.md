# Hook 候選：Cerebras RAG 第 3 則（`rag-planner-single-round-vs-agentic` ＋ `retrieval-reasoning-decoupling`）

這一則的內容骨架：搜尋系統裡有一個 **planner**，用一個比工具還便宜的小模型決定「這次該用哪幾個工具」，
只決策一次、平行查一次、最後合成一次答案，沒有「不夠就回頭再查」的迴圈，所以作者判斷它是**單輪 pipeline，不是 agentic loop**
（「用了 LLM 做決策不等於 agentic」；這個判斷是作者讀完後自己推導的，Cerebras 文章沒有直接講，**用了就要連同這個限定一起出現**）。
另一條線是**檢索與推理解耦**：每一路檢索各自摘要、最後再合併摘要，有三個問題；改成檢索只吐原始證據、推理全部留到最後一次 synthesis；
不是所有推理都要消除（SQL 這種「計算」要保留，但藏進工具內部）；同一套原語對外兩種介面（給 AI 用的 MCP 不含 planner、給人用的 Web UI 全包）。

**相鄰樣態**：第 2 則是「並列重點」，所以這一則不能用並列式；第 1 則是「讀者疑問」（不相鄰，可重複）。
排序照人的偏好：清楚直白的放前面，反差式放後面。

---

## A（讀者疑問）

- **主標**：用了 LLM 做決策，就算是 agentic 嗎？
- **副標**：Cerebras 的搜尋讓 LLM 決定這次查哪些工具，
  但只決策一次，沒有「不夠就回頭再查」。
- 沒看過系列的人會懂什麼：知道主角是「用 LLM 決定查什麼的搜尋系統」，而且有一個大家常搞混的問題要回答。
- 引用：`c1`、`c13`、`c14`（都是部落格判斷，帶「作者自己推導」的限定條件）
- 風險：「不算 agentic」是作者的判斷，主標用疑問式沒下結論，副標只描述結構；限定條件要在內文第 3 張以內出現。這就是系列檔原本暫用的標題。

## B（情境痛點）

- **主標**：搜尋每次都把所有工具叫一遍？又慢又貴
- **副標**：Cerebras 先讓一個比工具還便宜的小模型，
  決定「這次該用哪幾個」，再平行去查。
- 沒看過系列的人會懂什麼：一個很具體的浪費問題，以及一個「先挑再查」的解法。
- 引用：`c3`、`c4`、`c5`
- 風險：「又慢又貴」要和 c3 一致（拖慢延遲、浪費成本，還可能拉低排序品質）；「平行去查」是 c8 的前提（工具彼此沒有依賴），內文要帶出。

## C（反直覺斷言）

- **主標**：用了 LLM 做決策，卻不算 agentic
- **副標**：差在有沒有迴圈和狀態：
  Cerebras 決策一次、查一次、答一次，就結束了。
- 沒看過系列的人會懂什麼：一個反直覺、馬上想知道為什麼的斷言，加上「迴圈」這個判準。
- 引用：`c1`、`c9`、`c13`、`c14`
- 風險：斷言句沒有疑問語氣，比 A 更容易被讀成「Cerebras 官方說的」；這是作者判斷，限定條件要早一點出現。封面會比 A 更吸睛也更需要忠實者重點看。

## D（代價與取捨）

- **主標**：只決策一次，搜尋最便宜，代價是不能回頭再查
- **副標**：發現證據不夠、或下一步要看上一步的結果，
  這種「單輪」的搜尋就接不住了。
- 沒看過系列的人會懂什麼：這個架構換到了什麼、又犧牲了什麼，適合喜歡看取捨的人。
- 引用：`c9`、`c10`、`c11`（都是部落格判斷，限定同上）
- 風險：「最便宜」要有依據（c5：planner 是整條線最便宜的一環，不是整個搜尋最便宜），措辭要小心別放大。

## E（反直覺斷言）

- **主標**：負責決策的模型，要故意比做事的更便宜
- **副標**：Planner 只做分類，不用生成，小模型就夠；
  省錢用的決策如果太貴，設計就自相矛盾了。
- 沒看過系列的人會懂什麼：一個違反直覺的設計原則（決策者比執行者便宜），白話就能懂。
- 引用：`c5`、`c6`
- 風險：只講了這一則的一個點，和整則主軸（單輪 vs agentic、解耦）對不齊，封面會比內文窄。

## F（情境痛點）

- **主標**：同一套搜尋，給 AI 用和給人用，為什麼不能長一樣？
- **副標**：給人用的把決策和合成都包起來；
  給 AI 用的，故意只留最基本的檢索工具。
- 沒看過系列的人會懂什麼：一個「同樣的功能、對不同使用者要不同包裝」的設計，跟現在大家在談的 AI agent 有關。
- 引用：`retrieval-reasoning-decoupling:c14`、`c15`、`c16`
- 風險：只涵蓋兩張卡裡的一小部分（MCP vs Web UI），和主軸（單輪 vs agentic、解耦）離得遠，做成封面會讓內文看起來離題。

## G（反直覺斷言）
- **主標**：它會挑工具、會同時查好幾路，就是不會說「我再查一下」
- **副標**：Cerebras 的搜尋用 LLM 決定這次查哪些工具，但查完一輪就作答。用了 LLM 做決策，不等於 agentic。
- 沒看過系列的人會懂：一個很像人的搜尋系統，缺了人最自然的那個動作。
- 引用：`c1`、`c9`、`c14`、`c4`（平行執行）
- 風險：主標約 25 字，封面會排 3 行；「不等於 agentic」是作者推導的判斷，內文要帶出這個限定。

## H（情境痛點）
- **主標**：答案藏在 A 的一句話加 B 的一張圖，分頭讀的 AI 拼不出來
- **副標**：每個資料來源先各自摘要再合併，沒有任何一個 LLM 看過全部證據。改成搜尋只撈原始資料，最後一次推理。
- 沒看過系列的人會懂：一個具體的失敗情境，加上「最後才一起讀」的解法。
- 引用：`retrieval-reasoning-decoupling:c10`、`:c6`、`:c8`
- 風險：「分頭讀」的是作者原本的系統（不是 Cerebras），內文要講清楚；主標約 27 字。

## I（讀者疑問）
- **主標**：每個來源先摘要、再把摘要合起來，為什麼反而漏東西？
- **副標**：摘要兩次就丟兩次細節，而且下游看不出丟了什麼。把推理留到最後只做一次，資料就只壓縮一次。
- 沒看過系列的人會懂：很多人直覺會這樣做，這裡告訴你為什麼不好。
- 引用：`retrieval-reasoning-decoupling:c11`、`:c8`
- 風險：只講到解耦這條線，planner 與「算不算 agentic」要靠內文。

## J（代價與取捨）
- **主標**：「先查 A，再看結果查 B」，這套搜尋做不到
- **副標**：它一開始就決定好查哪些工具、同時查完就結束。真實問題常常要看過第一輪結果，才知道還要查什麼。
- 沒看過系列的人會懂：這種設計的界線在哪裡，一句話就有畫面。
- 引用：`c10`、`c11`、`c9`
- 風險：封面偏負面，像在批評 Cerebras；內文要把它換到的東西（便宜、可平行）講出來。

## K（反差）
- **主標**：整條搜尋線最便宜的小模型，負責決定要叫哪些工具上場
- **副標**：它只從清單裡挑工具、不用寫出答案，小模型就夠。用來省錢的決策要是比工具還貴，就自相矛盾了。
- 沒看過系列的人會懂：一個違反直覺的分工：決定權給最便宜的那個。
- 引用：`c5`、`c6`、`c3`
- 風險：只涵蓋 planner 一塊；「最便宜」要用卡上「整條處理線裡最便宜的一環」的範圍。

## L（建議）
- **主標**：搜尋的時候先別想，推理留到最後一步一次做完
- **副標**：搜尋工具只撈原始證據，不推理、不摘要；所有證據攤在一起，最後才讓 LLM 推理一次。
