# hook 候選（第 2 則：prompt-repetition-free-lunch-latency）

前一則（第 1 則）是「反直覺斷言」，這則用「讀者疑問」。Claude 選 A。

| # | 樣態 | 主標 | 副標 | 沒看過系列的人會懂什麼 |
|---|---|---|---|---|
| A ✓ | 讀者疑問 | 提示詞貼兩次、輸入變兩倍，為什麼幾乎沒變慢？ | 多出來的字，落在 GPU 能同時算的讀題階段；真正花時間的是一個字一個字寫答案，而答案長度沒變 | 有個做法把輸入加倍卻不慢；答案的骨架在副標 |
| B | 數字落差 | 輸入多一倍，時間差通常只在毫秒等級 | 1000 個和 500 個 Token 一起算，GPU 幾乎一樣快 | 具體，但「毫秒」只講讀題那一段，容易被讀成整體延遲 |
| C | 代價與取捨 | 免費的午餐？提示詞貼兩次，用閒著的算力換理解 | 讀題時 GPU 有多餘算力；寫答案的長度沒變，等待時間接近原本 | 有反差；「免費午餐」要看完才懂 |
| D | 正面對決 | 貼兩次 vs CoT：都想讓 AI 讀懂，只有一個會拖慢 | CoT 讓模型多寫字；Prompt Repetition 只把輸入拉長，答案長度不變 | 對知道 CoT 的人有感，一般人不認識 CoT |
| E | 情境痛點 | 怕提示詞太長拖慢 AI？先分清讀題和寫答案 | 讀題可以一起算，寫答案只能一個接一個 | 實用，但沒點出 Prompt Repetition |

選擇理由：A 直接問讀者心裡的疑慮（輸入兩倍怎麼可能不慢），副標給答案骨架；和第 1 則的反直覺斷言錯開。B 的數字只講讀題那段，放主標會讓範圍看起來比卡大，所以留在第 2 張。
