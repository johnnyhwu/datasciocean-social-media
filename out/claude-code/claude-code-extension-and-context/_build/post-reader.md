### 第 3 張
版型：context
主標：先搞懂三個詞：模型、Harness、Context
補充：Claude Code 是 Anthropic 推出的 AI 編碼工具，可以看成三層：固定不變的模型、包在外面的 Harness、動態組裝的 Context。這一則看後兩層。
表列：模型｜負責理解任務、推理的 Claude 本身，固定不變。
表列：Harness｜包在模型外面的那一層：給模型工具，並管理它看到什麼。
表列：Context｜模型每一輪（每回應一次）看得到的所有內容：對話、讀進來的檔案、指令的輸出。

### 第 4 張
版型：diagram
主標：只靠固定的工具，不夠應付實際任務
補充：工具是模型能呼叫的動作，例如讀檔、改檔、跑指令。只靠模型加固定的工具清單，對編碼 Agent 實際遇到的任務太過僵化，所以 Harness 多開三個擴充點。
示意圖（sockets）上的文字與數字：Skills｜教它某件事怎麼做｜Hooks｜固定節點自動執行｜MCP｜接上外部的服務｜Harness 多開的三個插孔
示意圖的畫面（sockets）：上方一條深色橫條，下緣三個插孔，各接一根金色插頭到下面三張卡（名稱加一句它解決什麼）

### 第 6 張
版型：diagram
主標：固定節點一到，Hook 就自動執行
補充：Hook 是 Harness 在固定節點自動執行的 shell 指令（直接下給電腦的指令）：Session（一場對話）開始時、工具執行前、Agent 回覆完成後。這是確定性的控制，每次照做，不靠模型自己決定。
示意圖（transcript）上的文字與數字：Hook　Session 開始時｜你：把這個檔案改好｜Hook　工具執行前｜工具　改檔案｜Hook　Agent 回覆完成後｜｜示意：金色菱形是 Hook 介入的地方
示意圖的畫面（transcript）：一個終端機視窗，一列一個動作（提示符號、工具呼叫、失敗、通過）；有標 feeds 的列，金色箭頭從那一列繞到下一列並寫上標籤；金色菱形的列是 Hook 在這個節點介入；

### 第 7 張
版型：diagram
主標：要保證規則被遵守，Hook 是對的位置
補充：Hook 是一般程式碼、不是模型呼叫，所以適合用來保證「模型本身無法被信任會可靠遵守」的規則。寫在 CLAUDE.md（專案裡給 Claude 讀的說明檔）的規則只是請求。
示意圖（intercept）上的文字與數字：「絕不能改這些檔案」｜工具　改檔案｜受保護就擋下｜沒問題才放行｜只寫在提示裡，靠模型遵守｜寫成 Hook，執行前檢查｜Hook 檢查｜檔案
示意圖的畫面（intercept）：上下兩條路：上面是一句話直接通到檔案；下面是工具呼叫先過一道金框的關卡（關卡裡列出檢查項目）才到檔案

### 第 8 張
版型：table
主標：Hook 能做的事，和要注意的結束碼
補充：Hook 可以擋下動作、自動整理，也能讓檢查失敗。

### 第 9 張
版型：diagram
主標：MCP：用同一套介面，接各種外部服務
補充：Model Context Protocol（MCP）讓 Claude Code 用共通介面，接上 GitHub、資料庫、內部 API 這類外部服務。每個服務（MCP server）自己說明有哪些工具，Claude Code 就能像用內建工具一樣用它。
示意圖（hub）上的文字與數字：Claude Code｜Slack 工作區｜工單系統｜私有 repo｜MCP：共通介面｜不必為每個整合，手刻一套客製化的工具程式碼
