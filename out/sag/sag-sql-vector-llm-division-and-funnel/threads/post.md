## 貼文正文（附下方全部圖片）

```text
SAG 不靠更強的模型，靠分工。

RAG 是讓 AI 先查資料再回答。SAG 把查資料這件事拆給三個元件：SQL 資料庫負責確定性的精確比對、把事件串起來；向量資料庫負責別名、同義詞、錯字這類模糊的部分；LLM 負責高價值的聯合判斷。

LLM 只在候選縮到 100 個以內才出場（Step 1 先用輕量 LLM 從問題抽出實體，是例外），所以 token 與 API 成本壓得很低。

代價：實體超過 50 個時只留前 50 名，Multi-Hop 串聯並非完全沒有損失。這是系列的第二則。論文：arxiv.org/abs/2606.15971
```
