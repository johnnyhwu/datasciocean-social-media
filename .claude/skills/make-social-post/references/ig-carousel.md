# IG 輪播的結構與每張的寫法

**硬上限 10 張**（`slides_max`）。基本骨架：

```
封面 → 脈絡 → 內容張（依積木） → 帶走（倒數第二張） → 系列地圖（最後一張）
```

實測的貼文是 9～10 張：封面、脈絡、5～6 張內容、帶走、系列地圖（雙卡貼文常到 10 張的上限）。

## 0. 版型規劃（先於寫字）

2026-10-08 的教訓：第一版先寫字、再套版型，結果一半的圖下半部是空海面，人連續兩輪要求「用滿」。**寫 spec 之前，先為每張內容張選好版型**，並寫出「這張的下半部放什麼」：

| 這張要講的 | 優先用 | 備註 |
|---|---|---|
| 一組數字比較（3～4 項） | `chart_bars`（補充可 3～4 行；3 條要有副標籤用 `subs_inline`） | 軸從 0 起；單位與誰減誰寫在補充 |
| 「A 是什麼、B 是什麼」的名詞、定義 | `context` 加 `rows`（名詞表），或 `table` | 名詞表放在第 2 張，圖上的術語都要在這裡或更早的張定義 |
| 兩種情況、兩個例子的對照 | `table`（2～4 列） | 鍵可寫「主｜指標名」；每列的值寫成完整一句 |
| 一個因果鏈（前提 → 這裡的情況 → 所以 → 就算…） | `table`（4 列） | 比純文字好讀 |
| 一個量表、基準對比（完美／亂猜／我們的） | `chart_bars` | 讓差距一眼看出來 |
| 結論 | `takeaway`，**先問再答**（`question`） | |

| 同一批對象的兩個量一起看（同單位） | `chart_bars` 的**成對橫條圖**（`value2`＋`legend`） | 兩個量共用同一個 0 起點與比例尺，不用雙軸；名稱下小字可放第三個資訊（例如準確度）；4 組以內，補充 3 行以內 |

純文字（海面版 `text`）只留給真的沒有東西可以畫的少數張；用了就要說得出為什麼。**帶數字的圖，先讀 `chart-thinking` skill**：要比什麼、圖有沒有直接支撐主標、讀者看不看得懂圖上的名稱。規劃時順便列出：這則圖上會出現哪些術語、各在哪一張定義（只能在同一張或更早的張，**不能只放在 Threads**）。

## 1. 內容積木（依觀念特徵挑選，不套固定模板）

| 積木 | 何時用 | 必要性 |
|---|---|---|
| 問題 | 讀者需要先知道痛點 | 選用 |
| 常識 | 觀念在推翻一個大家以為的事 | 選用 |
| 機制 | 有「怎麼運作」，一步一張 | 選用 |
| 錨點 | 例子、數字、案例 | **必要** |
| 證據 | 實驗數字、對照結果 | 選用 |
| 限制 | 限定條件、什麼情況下不成立 | **卡上有才放，沒有就省略，不從別處補** |
| 評價 | 卡上的評價主張 | 選用，最先被砍 |

依主張的 `importance` 由上往下取：主軸、機制、最重要的錨點先放，評價與次要證據放後面。

## 2. 脈絡張

第一句交代「這是什麼」，後面才講「為什麼在乎」。依卡的 `context_type`：

| context_type | 脈絡張寫法 |
|---|---|
| `bound_to_source` | 這篇論文或產品在問什麼問題；系列內可共用 |
| `evidence_from_single_source` | 一句話交代方法來源（誰提出、做什麼），再講為什麼在乎。內容張凡是方法的設計，主詞都要是方法名。**脈絡張必須引用 `role: context` 的主張**（程式 A 檢查） |
| `standalone_classic` | 你會在哪裡遇到這個概念；論文只在中段出現一次當轉折 |

## 3. 帶走與系列地圖

- **帶走張**：一句話總結，可以截圖收藏。結尾給可執行的動作，不用空泛提問。**一律先問再答**（`question`，2026-10-08 人決定）：先問一個讀者想問的問題，再給答案，看的人才知道這句話在回答什麼。部落格判斷不必標「我的判斷」。其他張的轉折處（例如「沒有證據時會怎樣？」）也可以先用補充開頭提一個問題。
- **系列地圖**：列出同系列所有則的 `planned_title`，標出「你正在看這則」，**不用「3/4」這類序號**（會暗示有先後依賴）。底部是導流行（見 `threads-and-caption.md`）。
- **獨立 post**：最後一張改成「延伸閱讀」，列 wiki 裡相關觀念已發布的貼文標題；沒有系列標籤、系列 hashtag。

## 4. 每張投影片的寫法

| 規則 | 內容 |
|---|---|
| 一張一件事 | 主標加補充加選用視覺 |
| 主標是結論句，不是主題標籤 | 只看主標，讀者要能知道這張的結論。例：「語意相似，不等於解法相容」，不是「相似度檢索的問題」 |
| 主標長度 | 渲染後最多 2 行（字數只當預檢；封面與內容張的預檢上限分開，見 `params.yaml`） |
| 補充 | 文字張 40～110 字；圖表與對照表最多 2 行（46 字內）；脈絡張最多 140 字。超過就由撰寫者刪，不放寬上限（2026-10-08 由 60／24／90 放寬：資訊密度太低） |
| 讀者是誰 | **沒有 AI 背景的一般人**（人的回饋，2026-10-10：「你做的 post 不是給其他 agent 或 AI 看，是給 human 看，這個 human 不要只限定是工程師」）。只知道 LLM、ChatGPT；其他名詞（Judge、題庫名稱、q、τ、基準、驗收集、推理強度、誤差範圍）輪播內要有白話說明。**寧可文字多一點、好懂，也不要精簡到讀者要猜**；多的文字放得下就放，放不下見 §5 |
| 口吻與白話 | 像在跟朋友解釋，不要像條列結論：完整句子、先講問題再講答案、術語**第一次出現就用白話講**（排序、校準、AUROC、分流、平均最高機率…）；可以用生活化比喻（改考卷、天氣預報），比喻只用來翻譯，**不帶進卡上沒有的事實、數字或主張**。主標仍是結論句，但不要把三個分號子句塞成一條（帶走張除外） |
| 不標「我的判斷」 | 人決定（2026-10-08）：圖與文字都不標，讀者本來就把整則貼文當成作者的產出。版型仍保留 `label` 小標籤欄位（右上角），要用在別的地方時再用 |
| 把每張圖用滿 | 每張圖都要想「下半部放什麼」：文字張的下半部是空的海面就是浪費。優先用對照表（`table`，可放 4 列、鍵可寫「主｜指標」）、橫條圖（`chart_bars`，`subs_inline` 讓 3 條自動拉開）、脈絡張的名詞表（`context` 加 `rows`）；補充可以寫到 4 行左右，圖與表會自動往下讓位。純文字張（海面版）只留給真的沒有東西可以畫的少數張 |
| 單位 | 準確度差距直接寫 %（人決定，2026-10-08），不寫「百分點」；補充裡要說清楚是誰減誰（例如「JEV 減 GPT-6」） |
| 數字要有比較對象 | 「recall 78.89%」不行，要寫「只呼叫 1 次找回 78.89%，呼叫 8.2 次找回 100%」 |
| 名詞第一次出現 | 自創名詞與縮寫第一次出現就附一句白話定義（放補充或角落小字） |
| 不放 | 公式、超過 3 點的條列、超過 3 列的表格、完整段落 |
| 錨點寫法 | 依 `anchor-writing-rules.md`（設計參數主詞要是方法名、官方宣稱主詞要是宣稱方、部落格推論標「我的推論」…） |
| 缺席型主張 | 直接寫「論文沒有提到…」，前提是卡上有這條主張。**「官方只拿標價」這種句子是缺席型主張**，卡上沒有就不能寫 |
| 圖片 | 圖上所有數字與名稱都要被引用的主張涵蓋。規則見 `design-series-visuals` |
| 無標點連續字數 | `word-break: keep-all` 對中文只在標點處斷行，連續約 13 字以上無標點會超出版心。標題與補充要有標點斷開（程式 B 的溢出檢查會擋，但自己先避開） |

## 5. 超過 10 張時的取捨，與「想加白話解釋但沒位置」

白話解釋要加進去、版面又滿了（表格補充超過 3 行、圖下面放不下、10 張已滿）時，**先砍評價與次要證據，再考慮合併或刪張；不縮字級、不擠字**。2026-10-10 的實例：決定不放「選擇集與驗收集的區別」「保守規則的細節」，換來表格能用完整句子解釋。

依優先順序由後往前砍，砍掉的留在 blog：

| 優先順序（高到低） | 內容張 |
|---|---|
| 1 | 問題或核心想法 |
| 2 | 運作骨架 |
| 3 | 最重要的結果（錨點） |
| 4 | 卡上有的限制 |
| 5 | 次要證據 |
| 6 | 評價（最先砍） |

**被砍內容若帶有某條已使用主張的限定條件，限定條件要挪到別張，不能跟著砍掉。**

## 6. 卡上內容不夠撐一張時：整張刪掉

貼文是卡的子集，不必用盡每條主張。例如整張卡只有一條主張的投影片，配的 Threads 串文想不重述圖、又不夾帶卡上沒有的東西，做不到（程式 A 重疊率超過上限）。結論：拿掉那張投影片與對應串文（串文與內容投影片一對一，投影片被砍，串文跟著消失）。

刪除只會減少內容，不新增忠實度風險，所以可以只用程式 A、B 驗證、不必再派審查者，但要在給人的報告裡說明刪了什麼。
