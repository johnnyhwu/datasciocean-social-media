# 錨點類型的寫法規則

每條主張在卡上有 `anchor_type`（定義在 `concept-wiki/docs/card-format.md` §6）。貼文用這條主張時，**寫法由類型決定**；忠實者逐區塊檢查，程式 A 對「部落格判斷」做提示。

**新增錨點類型時，必須同時在這裡定義寫法**（兩個 repo 的契約，見 concept-wiki 的 CLAUDE.md）。

| 類型 | 寫法規則 |
|---|---|
| 實驗結果 | 可直述，但要有比較對象與適用範圍 |
| 設計參數 | 主詞必須是方法名（「X 的做法是…」），不得用「最佳」「應該」 |
| 官方宣稱 | 主詞必須是宣稱方（「官網宣稱…」「官方的做法是…」） |
| 第三方實測 | 標明測試方與比較對象 |
| 數學推導 | 可直述，附數字與前提假設 |
| 外部研究引用 | 寫成「某研究顯示…」，語氣保守 |
| 原作者解讀 | 必須標「作者認為」 |
| 部落格推論 | **定義（2026-10-24 契約擴充）**：blog 對原因或機制的解釋或推測，論文沒有實測驗證，**不論 blog 有沒有明標「推論」**（好壞、該不該、值不值得的評價仍是部落格判斷）。寫法：**不必標「我的推論」或「我的想法」**（人 2026-10-24 決定：讀者本來就把整則貼文當成作者的想法，標了反而多餘），直接以作者口吻寫；但**語氣不得比卡強**，不寫成論文已驗證的事實（卡上寫「這個落差來自資訊密度」，貼文可寫「落差可能來自資訊密度」，或照卡直述但不加「實驗證明」這類驗證語氣） |
| 部落格考證 | 標明是換算或解讀，附算式或前提（例如「依我的整理」） |
| 部落格判斷 | 可以直接以作者的口吻寫，**不必標「我的判斷」**（人的決定，2026-10-08：讀者本來就把整則貼文當成作者的產出）；但不得寫成卡上沒有的普遍事實、不得比卡上的句子更強，卡上的限定條件照樣帶出 |
| 背景說明 | 直述，不當成本文的發現，不加「我的」 |
| 部落格舉例 | 必須標明是假設的例子，不寫成實際發生的事 |
| 社群評論 | 寫成「某社群最高票留言指出…」，不當成事實，不當成權威結論 |

## 通用規則

- 數字要有比較對象：「25 倍」不行，要寫「Every 實測對比 Fable 5.1 快 25 倍」。圖表上的單位與比較對象也要寫明（只寫「倍」沒說是速度要判錯）。
- 卡上沒有的比較詞、全稱詞不能出現（更、最、都、全、幾乎、常常、總是、從不、沒贏、遠不如、大幅、完全、一定，程式 A 檢查）。
- 限定條件跟著主張走：用了主張就要帶出它的 `qualifiers`（用 `quals` 標記）。
- `author_confirmed` 的主張寫法取保守，不得比卡上的句子更強。

## 參考圖（卡上主張附的 `figures`；2026-10-24 契約，`concept-wiki/docs/card-format.md` §4.2）

卡上有些主張附了 blog 的圖（多半是論文的 Figure 或 Table 截圖）。**圖是參考，不是證據。**
1. **不直接貼原圖。** 貼文裡的視覺一律重製：LLM 只寫內容規格，由程式畫（CLAUDE.md 規則 8）；`render.py` 的輸出不含任何原圖像素。
2. **內容以主張為準。** 重製圖上的數字、標籤、比較關係要和**這張引用的主張文字**一致。主張沒提到的圖上內容（表格裡主張沒用到的欄、圖上其他的格子與線條），**預設不放**：上游沒有逐條查證，而且常沒有比較對象（程式 A 對它發 HINT「數字不在引用主張原文」）。
3. **不加新資訊。** 不因為圖上有，就在貼文加主張沒有的判斷、數字、結論。
4. **範圍不放大。** 保留原圖標明的範圍與條件（資料集、模型組、設定、圖例）；主張的 `qualifiers` 照常帶出（含 `source: figure_caption` 的：圖說只用來交代範圍）。表格只取一欄、拿掉圖例時，確認沒讓範圍看起來比實際更廣。
5. **出處。** caption 由 `build_package.py` 自動註明「圖片來源：第 N 張（圖號）改繪自原始論文的圖表」；圖與文字都不要把論文的圖表說成我們自己做的實驗。
6. **圖說（caption）不是貼文文字。** 不要整段搬進貼文；它沒經過主張那套審查。
7. **重製後獨立審。** spec 的投影片寫 `fig_refs`（`"<article>/<src>"`），`build_package.py` 產生 `_build/figure-review.md`，派重製圖審查者（`figure-prompt.md`）對「原圖 × 主張 × 重製圖」逐項核對；`verify_figure.py` 驗證。**不要假設上游已查證圖上的內容。**
8. **圖看不懂或太複雜就不用。** 寧可只用文字，不要重製出一張自己也無法保證正確的圖。完全不用卡上的圖是合法的；沒有 `figures` 的主張與舊卡完全不受影響。
9. **`pending_author_confirmation` 的主張，它的圖也不能用；`author_confirmed` 的主張，圖可用、寫法取保守。**

## 論文書目資訊（作者、年份、arXiv 連結）

（人同意，2026-10-23）卡上有就直接引用。卡上沒有、但貼文提到某篇論文時，**預設補作者與年份**；外部查證（WebFetch arXiv 或官方頁）限**書目資訊**，不含任何論文內容，並在 spec 與審查派發訊息標明「來源：外部查證，非卡」，列為忠實者的放行項；網址用 `latin_allow` 讓程式 A 放行。查不到就不寫，不猜。

## 第一人稱的「我的判斷」

**2026-10-08 人決定：不必再標「我的判斷」**（圖與文字都不用）。貼文口吻直接以論文或官方為來源，卡上的部落格判斷用作者的口吻直述即可，不說「我的文章寫過」。仍要守的：不加卡上沒有的判斷、不比卡上的句子更強、限定條件帶出。「部落格推論」也不必標「我的推論／我的想法」（2026-10-24 人決定，但語氣不得比卡強、不寫成已驗證）；「原作者解讀」仍標「作者認為」（它不是本文作者的定論）。以前的貼文（`jev-cascade-overview`）已發布，維持原樣。

## 部落格判斷與官方宣稱混在同一句時

拆成兩個區塊或兩個句子：官方宣稱的部分以官方為主詞，部落格判斷的部分以作者的口吻另寫一句。不要用一個無主詞的句子同時承載兩種來源。
