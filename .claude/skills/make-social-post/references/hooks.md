# hook

hook 是 IG 封面的主標與副標、Threads 正文的第一句。每個觀念先產生 **6～10 個候選，橫跨至少 3 種樣態**，由人挑。一批貼文的 hook 一次挑完（用 AskUserQuestion，每個觀念一題，附候選的完整主標與副標）。

## 樣態（開放清單）

| 樣態 | 例子 |
|---|---|
| 數字落差 | 號稱快 193.6 倍，第三方實測最高約 25 倍 |
| 反直覺斷言 | 快 5 倍、25 倍、193.6 倍，可能說的是同一個產品 |
| 讀者心中的疑問 | 看 AI benchmark，為什麼要先問「標準答案是誰定的」？ |
| 代價與取捨 | API 省到八分之一，代價是兩成內容回不來 |
| 情境痛點 | 長文件丟給 LLM 太貴？ |

## 規則

- **主標負責好奇，副標負責具體**（交代主題與領域，讓人判斷這和我有關嗎）。
- **不能騙人**：滑到最後一張時，讀者不該覺得被封面騙了。限定條件至少要出現在某一張圖上。**封面不能比內文說得更滿。**
- 論文或產品的自創名詞放副標或脈絡，不放主標（業界通用詞如 RAG、RLHF 可以）。
- 具體勝過形容詞，不用「驚人」「必看」。
- **hook 也要引用卡上的主張（`hook.refs`），並過程式 A 與忠實者**：hook 裡的數字、比較詞、「我的判斷」標記都跟內文一樣受檢查。
- 候選都不合格，視同寫不出 hook，該格式標 `unsuitable`。
- 相鄰兩則（含跨系列）的 hook 樣態不同（`batch_check.py` 檢查）。

## 人挑了之後，hook 被審查者要求改字怎麼辦

第一次實跑兩次發生：人挑的 hook 文字，忠實者要求改（部落格判斷要標「我的判斷」、「約」不能丟掉、少了「換任務」限定）。處理：

1. 改的幅度盡量小，只改到審查者指出的問題。
2. **一定要在報告裡告訴人**：原文、改後的文字、改的原因。不要靜靜改掉人選的 hook。
3. 若改完已經不是人選的那個意思，回頭請人重選。

實例：A3 副標「想要快又要彈性，Jev 想補中間那塊」是部落格判斷，改成「我的判斷：Jev 想補的，正是這兩條路中間的空隙」，主標加「換任務」；B4 的「5 倍」改成「約 5 倍」。
