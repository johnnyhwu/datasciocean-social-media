# hook

hook 是 IG 封面的主標與副標、Threads 正文的第一句。**目標是吸引讀者點擊，同時不欺騙**（人確認，2026-10-06）。

## 流程（省 token，也省人的時間）

1. **自己先提 5～6 個候選**，橫跨至少 3 種樣態，要大膽、有反差、口語、活潑，不要抽象。**提之前先用「沒看過這個系列、沒聽過 JEV 的人」的角度檢查每一個**：只看主標與副標，一眼知道這篇在講什麼事、跟我有什麼關係嗎？（2026-10-10：第一輪候選因為要先看過別則才懂，人全都不滿意。）
2. **最多派一次**乾淨的小模型 subagent（haiku）當讀者，只給候選的主標與副標，不給卡、不給 repo。讀者角色是「沒看過這個系列、對 AI 只有模糊概念的一般網友」，**不要設定成工程師**（工程師角色會偏好「決策價值」，選出的 hook 偏保守）。請它回答：一眼看得出在講什麼嗎、最想點的前 2 名、哪則像標題黨、哪則最容易誤會成別的意思。
3. 讀者的結果**只當參考**（樣本只有一個）。**最後由人挑**：**用純文字列出候選**，每個寫完整主標、完整副標，加一句「沒看過系列的人看到會懂什麼」，**不用 AskUserQuestion**（人 2026-10-10 兩次拒絕：選項太簡短、沒有空間說明，人想先釐清）。
4. 教訓：三輪 haiku 讀者的排序，人都不滿意，最後是人用感覺選的。所以不要連續多輪「讀者選前三名、再補、再選第一」。

## 寫法

| 規則 | 內容 |
|---|---|
| 獨立可懂 | **不假設讀者看過系列、認識 JEV**（人的偏好，2026-10-10）。主標與副標合起來，沒看過系列的人要一眼知道主角是誰、在做什麼、跟我有什麼關係。主角優先用**身分描述**（「便宜的 Judge」「GPT-6」）；品牌名（JEV）不強求放封面，除非品牌名本身就是吸引點。第 1 則「便宜判官 Jev 先判…」的寫法是舊偏好（名字加身分詞），現在不強制 |
| 主標＝讀者的情境，副標＝答案的骨架 | 例：主標「想用便宜的 Judge 幫 GPT-6 省錢？得先闖兩關！」（痛點加懸念），副標兩行寫兩個條件。人選了這個結構，但不是唯一結構 |
| 反差、口語、活潑 | 「居然」「收尾」「單打」「得先闖兩關」「也可能會掉分」這類口語動詞、語氣詞、問句、驚嘆號都可以用；它們是語氣，不是事實主張。人的偏好是**活潑、自然、像在說話**，不要書面語 |
| emoji | **圖上不放 emoji**（內嵌字型沒有，要加得內嵌約 10 MB 字型、改模板 hash、對比度也量不準；人 2026-10-10 同意）。圖上用字型內有的符號（「→」「✓」）；emoji（➡️ 等）只放 Threads 正文與 IG caption |
| 並列重點 | 貼文真的有兩三個並列的重點時，副標可以用標號加箭頭分行（「第一關 → …」「第二關 → …」），是樣態之一，不強制；注意標號會暗示先後（編輯審查者會提醒），確定有先後或人選了就留 |
| 副標負責讓人一眼懂 | 寫答案的骨架（做法、條件）；**數字與範圍不強制**（人 2026-10-10 同意）。有數字時仍要寫明比較對象與範圍（例如「RewardBench 上」） |
| 可以沒說完整 | 留白、懸念、省略機制都可以，這是吸引點擊的來源 |
| 具體勝過形容詞 | 不用「驚人」「必看」 |
| 副標要白話 | 一般人看得懂：數字附單位與比較對象（「跟 GPT-6 比…差距在 2%」，不寫「差 2 點內」），不用內部詞；準確度差距寫 %（2026-10-08 人決定） |

## 不能騙人的界線（忠實者依此判斷；見 faithful-prompt.md）

主標與副標**合起來看**：(a) 每一句字面上都能由卡支持，範圍可以由副標限定；(b) 不暗示卡上沒有的範圍或結論（例如把某基準上的略勝說成整體勝）；(c) 被省略的限定條件在內文某處出現；(d) 讀完整則不會覺得被騙。

- 卡上寫「略勝」，封面寫「贏過」可以：贏是真的、範圍已限定，代價是讀者可能期待更大的差距，人接受。
- 遇到「更吸引人」與「更保守」的取捨，**預設選更吸引人**，只要符合上面四條。
- **hook 也要引用卡上的主張（`hook.refs`），並過程式 A 與忠實者**：數字、比較詞都跟內文一樣受檢查。

## 版面限制

封面主標最多 2 行（程式 B）。放不下範圍限定時，把範圍放副標，不要為了塞進主標把 hook 改弱（曾被迫改成「某基準」，人覺得怪）。要放寬成 3 行是改 `params.yaml` 與程式 B，由人決定。

## 樣態（開放清單）

| 樣態 | 例子 |
|---|---|
| 數字落差 | 號稱快 193.6 倍，第三方實測最高約 25 倍 |
| 反直覺斷言 | 便宜的 Judge JEV 先判，成績居然贏過 GPT-6 單打 |
| 讀者心中的疑問 | 看 AI benchmark，為什麼要先問「標準答案是誰定的」？ |
| 代價與取捨 | API 省到八分之一，代價是兩成內容回不來 |
| 情境痛點 | 長文件丟給 LLM 太貴？ |

相鄰兩則（含跨系列）的 hook 樣態不同（`batch_check.py` 檢查）。候選都不合格，視同寫不出 hook，該格式標 `unsuitable`。

## 人挑了之後，hook 被審查者要求改字怎麼辦

1. 先看審查者的 blocker 是不是違反上面 (a)(b)(c)(d)；只是「語氣」或「留白」不算違反，不要為了過審把 hook 改弱。
2. 真的要改，改的幅度盡量小，只改到審查者指出的問題。
3. **一定要在報告裡告訴人**：原文、改後的文字、改的原因。不要靜靜改掉人選的 hook。
4. 若改完已經不是人選的那個意思，回頭請人重選。
5. 與審查者對語氣或留白有爭議時，標「爭議」交給人（人可以改審查者提示詞）。

實例：
- 封面主標「成績居然贏過 GPT-6 單打」被擋「沒限定 RewardBench」；改成由副標限定範圍（「RewardBench 上，…」），並在忠實者提示詞加上「封面可以沒說完整」，主標保留人挑的樣子。
- 2026-10-10：副標「丟給 GPT-6 的門檻要設對，設太鬆也可能會掉分」被擋「範圍被放大」（卡上掉分的反例是 GPT-5.6 Sol，GPT-6 選出的門檻沒有掉分）；改成「丟給強的 Judge」，語氣與其他字都不動，並告知人。**人同意（2026-10-10）：遇到這類情況，照這個做法——把被擋的專名換成卡上支持的更廣說法，不改語氣，並在報告裡告知。**
