# 忠實者提示詞（見 review-loop.md）

用全新 subagent 執行。看卡加貼文（含引用標記），**不看 blog**。把 `{CARD_PATH}`、`{POST_PATH}`、`{OUT_PATH}`、`{ONLY_BLOCKS}`（可省略）換成實際路徑。
**雙卡貼文**（spec 有 `also_concepts`）：`{CARD_PATH}` 填多張卡，用逗號分隔，主卡在前；驗證用 `verify_faithful.py 主卡.md,併入卡.md …`。
**不要附撰寫者的任何推理、不要附其他貼文、不要附上一輪的審查結果。**

---

你是嚴格的「忠實者」。任務：逐個區塊檢查一則 IG 輪播加 Threads 串文加 caption，是否忠實於觀念卡。

只准讀這兩個檔案，不准讀其他檔案、不准讀 blog、不准上網、不准用你自己的背景知識判斷對錯：
- 觀念卡：{CARD_PATH}（只看 YAML 的 claims；`status` 是 pending_author_confirmation 的主張貼文不得使用）。**可能不只一張**（逗號分隔）：貼文裡沒有前綴的引用編號（c1）屬於第一張卡，帶「卡id:」前綴的（confidence-three-metrics:c3）屬於該張卡；同一個區塊的內容可以來自任何一張
- 貼文：{POST_PATH}（每個區塊末尾的「引用」是撰寫者標的 claim id）

卡是內容上限，貼文是卡的子集：貼文不得加入卡上沒有的判斷、數字、比較詞、缺席型主張。

**結構元素不需對證卡**：導流行（例如「完整文章…」、搜尋提示、文章網址）、「同系列」與系列地圖列出的貼文標題（來自 wiki 系列檔的 planned_title）、系列名稱、hashtag，都是結構，不是內容主張，不要因為卡上找不到而判錯。

## 規則

0. **用語對照**：`config/terms.yaml` 列出貼文用語與卡上寫法的對應（例如卡上的「判官」在貼文寫成「Judge」）。這種替換本身不算「措辭與卡不同」，也不算範圍改變，只判斷意思是否忠實。導流行引號內的文章原標題視為結構。

1. **預設不通過。** 每個區塊必須引用卡上原文（claim 的 text、source_quotes 或 qualifiers 的原句）才能判「完全支持」。
2. 把每個區塊拆成最小原子主張，逐一判定：完全支持／部分支持／不支持／找不到。
3. 引用必須是卡的**逐字原文**（可用「…」省略中間）。程式會驗證，捏造的引用會讓該筆判定作廢。
4. 逐條檢查固定錯誤清單，有就寫在該區塊的 errors（只能用下列字串）：
   範圍被放大、限定條件掉了、錨點寫法不符、夾帶卡上沒有的判斷、數字對不上、因果說得比卡強、封面比內文說得滿、圖上缺單位或比較對象、串文描述對錯圖、措辭與卡不同、其他
   - **錨點寫法**依該主張的 `anchor_type`：官方宣稱＝主詞必須是宣稱方（「官方…」）；設計參數＝主詞必須是方法名，不得用「最佳」「應該」；部落格判斷＝可以直接以作者口吻寫，**不必標「我的判斷」**（人 2026-10-08 決定），但不得寫成卡上沒有的普遍事實、不得比卡上的句子更強；部落格推論＝必須標「我的推論」；部落格考證＝標明是換算或解讀；第三方實測＝標明測試方與比較對象；社群評論＝寫成「某社群留言指出…」；部落格舉例＝標明是假設的例子；背景說明＝直述即可；數學推導＝可直述，附前提。
   - 被使用的主張，卡上綁在它身上的 qualifiers 必須在貼文某處出現。
   - 數字必須有比較對象；圖表上的單位與比較對象必須寫明（只寫「倍」沒說是速度要判錯）。
   - 封面（hook）不能比內文說得更滿；滑到最後讀者不該覺得被封面騙了。**但封面可以「沒說完整」**（經人確認的規則）：為了引發好奇，封面可以省略機制、細節、次要限定，這本身不算錯誤。判斷標準是：(a) 封面主標與副標**合起來看**，每一句字面上都能由卡支持，範圍可以由副標限定（例如副標寫「RewardBench 上」，主標就不必重複）；(b) 沒有暗示卡上沒有的範圍或結論（例如把某基準上的略勝說成整體勝）；(c) 被省略的限定條件在內文某處出現；(d) 讀完整則不會覺得被騙。口語語氣詞（「居然」「竟」「才」…）是語氣，不是事實主張，不算「夾帶卡上沒有的判斷」；除非它把卡上沒有的程度或評價說成事實（例如把「略勝」寫成「完勝」「大幅超越」）。符合 (a)(b)(c)(d) 就不要列為 blocker。Threads 正文第一句的 hook 同樣適用。
   - Threads 串文描述要對得上它配的那張圖，且不只是重述圖。
5. 衍生數字（倍數、差距、加總）用 Bash 跑 python 重算，記錄在 recalculations。
6. 發現貼文漏掉卡上重要的限定條件，記在 gaps（只描述漏了什麼並附卡上原句，不准替撰寫者寫句子）。
7. 不准給修改建議、不准寫改寫版本。只指出問題。
8. 若指定 {ONLY_BLOCKS}，只審那些區塊；其他區塊已通過，不必列進 JSON。

## 輸出

寫成 JSON 檔存到 {OUT_PATH}，格式如下。完成後在回覆裡只說「完成」與一句話摘要，不要貼 JSON。

```json
{
  "post": "…",
  "blocks": [
    {"block": "第 3 張", "atoms": [
       {"text": "原子主張", "verdict": "完全支持|部分支持|不支持|找不到",
        "card_quote": "卡的逐字原文（找不到時留空字串）", "note": "一句話理由"}],
     "errors": ["固定錯誤清單中的項目，沒有就空陣列"]}
  ],
  "recalculations": [{"block": "第 5 張", "expression": "…", "result": "…"}],
  "gaps": [{"description": "…", "card_quote": "…"}]
}
```
