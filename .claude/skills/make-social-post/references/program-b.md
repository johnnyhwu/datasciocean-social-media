# 渲染與程式 B（`render.py`）

```
spec.json → 填入該系列的 HTML 模板（內嵌字型）→ Playwright 無頭瀏覽器截圖 1080×1350 PNG
          → 程式 B 逐張檢查（量 DOM 與實際像素）→ 通過後才交給 subagent 審查
```

`uv run python .claude/skills/make-social-post/scripts/render.py out/<series>/<concept>/_build/spec.json [--only 3,5]`

輸出：`ig/NN.png`、`checks-b.json`（每張每項檢查的結果與 `template_hash`）、`alt-text.json`（每張替代文字，由主標加補充自動產生；系列地圖是標題加各則 planned_title）。`--only` 只重渲指定張。**已發布的貼文預設拒絕重渲**（會覆寫它在本機的圖）；確定要重做（例如改版型後讓 template hash 一致）才加 `--force`，並先確認只有預期的檔案會變（2026-10-08 實測：重渲第 1 則只有第 9 頁 PNG 與兩個機器紀錄檔有變）。`build_package.py` 同樣。結束碼 1 = 有檢查不通過。規格記錄模板版本的 hash，同一系列「還沒發布」的貼文必須用同一版模板（`batch_check.py` 檢查；已發布的貼文不比對，也**不要為了讓 hash 一致而重渲它們**：2026-10-10 實測，強制重渲第 2 則會讓 2 張表格的 PNG 與系列地圖改變，本機圖就和網路上已發布的對不上；模板改了，已發布貼文記的就是舊 hash，這是預期的）。

## 程式 B 檢查項目

| 檢查 | 說明 |
|---|---|
| 尺寸 | 頁面不超過 1080×1350，無捲動溢出 |
| 字型 | Noto Sans CJK TC 已內嵌載入（不是系統字型） |
| 邊界 | 所有文字距左右邊緣至少 40px；文字與圖形（含表的橫線）不得超出版面下緣（至少留 20px）。表太高、補充太長會掉出頁面，這項檢查才擋得住 |
| 文字溢出 | 文字框內容寬度不超過框 |
| **不重疊** | 文字與文字、文字與圖形都不重疊。**圖形邊界框必須含線寬**（SVG 的線，邊界框的寬或高為 0，不含線寬會永遠判定沒重疊）。純裝飾的圖形（class `deco`）不算 |
| 字級 | 最小 28px；所有字級都在允許集合 {28, 34, 38, 40, 56, 72, 76} 內 |
| **對比度** | 取文字框外緣四角（內縮 2px）的**實際背景色**計算（量截圖像素，不用設計稿的色碼），至少 4.5 |
| 換行 | 標題與補充用 `word-break: keep-all`，用詞界分段檢查「換行不拆詞」（例如「倍數」不能被拆成「倍／數」）；末行至少 2 字 |
| 數字與單位不拆行 | 標題與補充在換行處，數字（含 % 與小數點）與緊接的中文字、或中文字與緊接的數字，不得被拆成兩行（例如「1.87／秒」「只轉／25%」）。渲染時 `bind_nums` 會把這種空白改成不斷行空格，這項檢查是保險 |
| 行數 | 主標最多 2 行（帶走張 4 行）；圖表與對照表補充最多 5 行（`render.py` 的檢查；字數預檢是 110 字） |
| 比例（圖表） | 橫條長度與數值成正比、軸從 0 起；測深繩長與數值成正比（水面為 0）、菱形中心落在繩端、刻度等距且間距 = 單位 × 每單位像素 |
| 強調 | 全圖只有一組強調元素（金色） |
| 系列標籤 | 與系列檔的 `name` 完全相同 |

投影片上每個數字都要出現在引用主張裡的檢查，在實作上放在**程式 A**（HINT 與比較對象 ERROR），不在程式 B。

## 重要經驗

- 程式 B 原本沒抓到「1.87／秒」被拆成兩行（詞界檢查看不出來），是看圖才發現。已加 `bind_nums` 與上表的檢查，回歸測試是 `tests/test_render_numunit.py`（用 `DSO_NO_NUMBIND=1` 關掉綁定，檢查必須抓到）。
- 圖表版型（`chart_bars`）數值很小的短條，配上長的副標籤時，數字標籤會壓到副標籤（重疊與對比度都會失敗）；副標籤要短，或改用 `chart_sounding`。

- **檢查全過不代表好看。** 撰寫者在交出前必須自己看一次渲染後的 PNG（例如標題把「倍數」拆開，是看圖才發現的）；用 `contact_sheet.py` 拼縮圖看整體節奏。
- 檢查寫進程式後，要用「故意做壞的版本」驗證檢查真的抓得到。
- `keep-all` 對中文只在標點處斷行：連續約 13 字以上無標點會超出版心。靠溢出檢查擋下（`check_a.py` 另有主標字數預檢）；寫標題與補充時自己先用標點斷開，而且**一個標點分段（逗號到逗號）盡量不超過一行的字數**，否則一行只放得下半句，行數會比預期多。
- 表格列高要依 keep-all 的實際斷行模擬估算（`render.py` 的 `est_lines`），否則列高會被低估而壓線。斷行點除了標點，還有 `」』）` 之後與空白（2026-10-10：「…2%」是…」瀏覽器在 `」` 後換行，估算漏了這個，列高少估一行、文字壓到下一條橫線）；不斷行空格（`\u00a0`）算 0.35 字寬、連字號後的不斷行字元（`\u2060`）不佔寬。回歸測試：`tests/test_render_numunit.py`。
- **連字號與數字單位**：`bind_nums` 在渲染時把 `GPT-6`、`GPT-5.6` 的連字號後加不斷行字元（不然會拆成「GPT-／6」），並把「數字與中文字之間的空白」改成不斷行空格；程式 B 的「數字與單位不拆行」檢查在連字號處也會抓（`DSO_NO_NUMBIND=1` 關掉綁定可驗證抓得到）。
- **成對橫條圖**（`chart_bars` 加 `value2`）的間距：數字用 40px 字，字框實高約 58px，橫條間距要到 60px 才不會讓兩個數字互相重疊；每組高 104px，4 組加圖例總高約 560px，所以 `body` 最多 3 行，不然會壓到圖註。
- 脈絡張加名詞表時，表從 `max(470, 補充底部 + 44)` 起；補充 1 行時多出的空間給名詞表。
- **程式 B 只量版面，不量「這張圖有沒有支撐主標」**；那要靠人看圖、`chart-thinking` 的評圖題，與審查者看圖（`review-loop.md`）。

## 渲染是確定性的

同一份 spec 與同一版模板，重渲的 PNG 逐位元相同。想確認「改了程式／搬了 repo 有沒有改壞渲染」，重渲現有發布包後比對 PNG 的 md5 即可。
