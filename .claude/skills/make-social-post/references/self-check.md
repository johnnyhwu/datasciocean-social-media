# 派審查之前的自檢清單

做 jev-cascade-overview 時，忠實者前幾輪的 blocker 幾乎都是撰寫者自己能先抓到的。每多一輪約 5～6 萬 token，所以**程式 A、B 都過、`build_package.py` 跑完之後，先照這份逐項看過 `post-with-refs.md`，再派審查者**。

## 逐項檢查

1. **每個數字的比較對象**：圖、標題、補充、Threads、**caption 的逐張摘要**、串文，每個數字旁邊都寫得出「跟誰比」。caption 摘要是由標題加補充第一個子句自動組成，標題裡的「27%」若沒寫是誰的 27%，caption 那行就缺比較對象。
2. **範圍標示是否對得上卡**：標題或副標用了「較難」「全新」「所有」之類的範圍詞時，回卡上找這個詞標在誰身上（例如「較難」只標在 JudgeBench，不是所有新任務）。
3. **封面**：主標加副標合起來看，每一句字面為真；範圍由副標限定；沒有暗示卡上沒有的範圍（見 `hooks.md`）。
4. **每個形容詞與程度詞**：對應到卡上哪一條主張？卡上寫「略勝」就不能寫「大幅」；語氣詞（居然、竟）可以。
5. **每條用到的主張的限定條件**：`quals` 標記的區塊，文字真的有把那條限定寫出來嗎？（只標 `quals` 不寫內容，忠實者會判掉。）
6. **串文描述**：不是重述圖；內容針對配的那張圖；若附帶了別張圖才有的資訊（例如把 JudgeBench 的事放在講別的任務的那則），搬到對的那則。
7. **名詞與範圍的歧義**：只看標題的人，會不會誤會成別的意思？例如「不要用」是不要用整個方法，還是只在某種情況下不要用？範圍要寫進標題。
8. **用語**：跑過 `config/terms.yaml`（程式 A 會擋）；導流行引用的文章原標題不改。
9. **排版（自己看圖）**：數字與單位有沒有被拆行（程式 B 現在會擋）、中英混排的詞有沒有被拆開（例如「推理型／Judge」）、短條圖的標籤有沒有擠在一起。

10. **每張圖的下半部放了什麼**（`ig-carousel.md` §0）：看渲染後的縮圖，有沒有哪張下半部是空的海面或大片空白？有就換成表或圖，或補內容。
11. **圖上的術語在哪裡定義**：逐張列出圖上出現的術語（AUROC、校準、平均最高機率、分流、串接…）。每一個都必須在**同一張或更早的張**用白話講過；**只在 Threads 定義不算**（只看輪播的人看不到）。背景詞清單內的詞除外。
12. **比喻畫的分界要和卡一致**：用比喻時，回卡上確認比喻的分界跟卡的分界是同一條。例：「改考卷、標準答案在旁邊」≠ 卡的「答案能直接讀出」；卡上「沒有證據可對照」是獨立的第三類，不是第二類的延伸。
13. **不把卡的詞升級**：卡寫「量的是不同的東西」，就不寫「互相獨立」；卡寫「落後很多」，就不寫「大幅」。口語化時最容易發生。
14. **封面副標也要白話**：給數字就附單位與比較對象，避免「差距」「點」這類內部詞；一般人看得懂誰比誰、差多少。
15. **caption 逐張摘要**：看自動組出來的那幾行：有沒有斷句、有沒有重複主標、判斷句有沒有被直述成事實。
16. **新欄位有沒有輸出**：改版型或加了 spec 欄位時，確認 `post-with-refs.md`、`ig/post.md` 都看得到那段文字（`build_package.py` 遇到不認得的欄位會報錯，但輸出格式要自己看一眼）。
17. **圖有沒有直接支撐主標**（`chart-thinking`）：主標說的事，圖上看得到嗎？（反例：主標寫「不會掉分」，圖只畫費用，準確度只在補充文字。）只看圖與主標，能講出結論嗎？
18. **專有名詞與題庫名稱在輪播內定義了嗎**：Judge、JEV、JudgeBench、PPE 這類名稱，同一張或更早的張要有白話說明；一般讀者看不到 Threads。定義只描述卡上說的事，不加用途（卡沒說「這是題庫」，就寫「兩組不同的題目」；Judge 這種背景名詞可用通用白話，不屬於卡的主張）。
19. **統計與實驗術語白話化**：「誤差範圍」「區間不含 0」「留作驗收」「推理強度」「選擇集」都要換成一般人看得懂的話，而且不改變卡的意思；換不出來就刪。**以沒有 AI 背景的人為讀者**（2026-10-10 人的回饋），不是工程師。
20. **主標的絕對詞不能漏掉卡上的條件**：「不會」「一定」「只會」要看卡上有沒有「失敗時」「選對時」「在這個任務上」這類條件，寫進主標（例：「門檻選對，失敗時只變貴、不掉分」）。
21. **小標籤與標題**：`label`（「第一關」）與標題開頭不要重複；caption 逐張摘要會自動去重，但圖上要自己看。
22. **圖與表放得下嗎**：補充超過 3 行的表或圖，下面的內容常放不下，程式 B 會擋「不超出版面下緣」；先把補充縮短，不要縮字級。需要更多白話解釋、又沒有位置時，**先砍評價或次要證據**，不縮字（`ig-carousel.md` §5）。
23. **改完 spec 要完整重跑**：程式 A → 程式 B → `contact_sheet.py` → `build_package.py`，再看一次縮圖；只重跑一部分，caption 與審查用文字會是舊的。

24. **卡上的限定詞逐個對照**（2026-10-12：忠實者擋下的 blocker 幾乎都是這類，撰寫者自己能先抓）：往往、大致（「內容大致是…」不能寫成逐字訊息）、可能、通常、「才」（卡寫「超過就會」，不能寫成「才需要」）、唯一（卡的「唯一」常只針對某個對象）、主觀性高、只在三個基準上、「看不到」指哪一份資料（不要寫成泛稱的「考題」）。貼文每次用到這些詞，回卡上核對範圍。
25. **機制白話的尺度**（人的決定，2026-10-12）：可以用白話解釋機制，只要不改變意思、不加新事實（新的原因、用途、數字、範圍）。問自己：這句白話拿掉後，卡的意思有沒有變？有沒有出現卡上沒有的因果？
26. **圖上格子的連續字數**：`word-break: keep-all` 下連續無標點的中文超過格子寬就溢出；寫 spec 時照 `ig-carousel.md` §4「圖上格子的連續字數」先斷句或縮短，不要等程式 B 才發現。
27. **用語一致、不交代資料缺口**：整則（含圖上文字、Threads、caption）用語一致（資料集三個名稱、目標 Agent、教練）；不寫「文章沒有提到／卡上沒有」。
28. **同圖型不連續 3 張以上**：看縮圖總覽，連續幾張長得一樣就換圖型（優先選 `brand-and-layouts.md` §4.2 裡有畫面感的）。
29. **雙卡貼文的引用標記**：句子的內容來自哪張卡，`refs` 就標那張卡的主張（帶 `卡id:` 前綴）；兩張卡有相同的背景主張（例如 c2）時，用到的那條要標對卡，限定條件也要標。

30. **機制類的張，白話解釋夠不夠**（2026-10-15 persona-aware-d2s 第 1 則：人看出第 7～10 張「太簡潔、有講但不清楚」，審查者沒抓到）：每張講機制的張，要回答「做什麼、怎麼做、為什麼這樣做」三件事；補充寫到字數上限就停通常是不夠的徵兆。問自己：讀者看完能不能用自己的話向朋友講一遍？講不出來就補，補不下就拆張或砍次要證據。
31. **圖拿掉，讀者少了什麼**（同上：第 9 張的示意圖「有點沒意義、文字解釋也亂」）：示意圖不只要支撐主標，還要比文字多給資訊（關係、流向、對比、順序）。圖上的字和補充文字說的是同一件事、圖只是把字裝進框裡，就換圖型或刪圖。
32. **並列的條件要標號**（同上：第 1 張三個條件讀起來像一個句子）：同一句裡並列 3 個以上的條件、步驟或限制，用「第一、第二、第三」或圖上的編號圓點分開。
33. **版面置中與對齊**（同上：第 2 張內文沒垂直置中、第 3 張文件 icon 沒置中）：程式 B 量的是不重疊與不超出，不量視覺平衡。看縮圖時特別看：內容塊在可用區域內是否上下均衡、icon 與文字是否對齊中線。
34. **前向指稱**：說明細節在別處時，一律寫「此系列的後續 post」，不寫「後面」（程式 A 擋）。

## 這份清單怎麼來

來自實測被忠實者擋下的類型：封面範圍、「較難」指誰、caption 數字沒有比較對象、串文把 JudgeBench 的限定放在無關的那一則、第 7 張主標的範圍不清楚（人看出來的）。新的類型出現就加在這裡。第 30～34 項來自 2026-10-15 的 persona-aware-d2s 第 1 則（人看完縮圖的回饋：解釋太簡潔、示意圖沒意義、並列條件沒標號、版面沒置中、「系列後面」被誤讀）。第 10～16 項來自 2026-10-08 的 `judge-readable-vs-derive`（空海面、術語只在 Threads 定義、改考卷比喻畫錯分界、「互相獨立」升級、`question` 欄位漏輸出）。第 17～23 項來自 2026-10-10 的 `cascade-complementary-errors`（人看完貼文的回饋：圖沒有支撐主標、名詞與統計術語看不懂、補充太濃縮；一般讀者審查抓到 Judge 與題庫名稱未定義；忠實者抓到主標的絕對詞漏了「失敗時」）。
