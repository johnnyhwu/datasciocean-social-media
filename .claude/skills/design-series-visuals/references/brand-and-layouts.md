# 品牌常數、版型、選圖與測深圖

所有 IG 圖片（含 Threads 附圖，兩邊共用同一套）的設計與渲染規則。渲染與程式 B 檢查在 `make-social-post` skill（`references/program-b.md`）。

## 1. 基本規格

| 項目 | 規格 |
|---|---|
| 畫布 | 1080 × 1350 像素（4:5 直式），所有張數比例必須一致 |
| 左右邊界 | 文字與關鍵元素距離左右邊緣至少 40px。個人頁面的格狀縮圖以 3:4 顯示，**左右各被裁約 34px**（上下不裁）。此數字來自討論時的資料，待手機實機確認 |
| 文字內距 | 預設左右各 80px |
| 圖片製作 | 只用程式產生（HTML 模板加無頭瀏覽器截圖）。**數據圖與文字圖一律不用 AI 生圖**（文字常出錯，數字可能畫錯） |
| 內容與外觀分開 | LLM 只產出內容規格 JSON（`make-social-post/references/spec-json.md`）；外觀完全由模板決定 |
| 重製，不用原圖 | 論文或文章的原圖一律依主張重畫（`CLAUDE.md` 規則 17、`anchor-writing-rules.md`「參考圖」） |

## 2. 品牌哲學與常數

**品牌哲學：深處的光。** 取自 podcast 封面（`assets/brand/image.png`）：鉛錘垂進一層層漸深的海，在最深處發出金光。深處是證據所在的地方，光是被挖到的洞見。畫面以米色紙面為底，以海浪的深淺為層次，金色只留給最重要的那一個元素。

| 常數 | 值 |
|---|---|
| 米色（底色） | `#F2E0C0` |
| Logo 藍綠（主標） | `#076876` |
| 深海（補充文字、深色底） | `#01353F` |
| 金色（強調，只給一個元素） | `#DDA642` |
| 淺藍綠、中藍綠、最深海 | `#69B4AA`、`#1F8A8D`、`#032027`（海浪色帶、面板、漸層；成對橫條圖的第一個量用中藍綠、第二個量用深海） |
| 字型 | Noto Sans CJK TC（開源授權），**內嵌在專案裡**（`assets/fonts/`），不依賴系統字型。字重只用 400 與 700，不用細字 |
| 字級 | 允許集合 {28, 34, 38, 40, 56, 72, 76}：主標 72～76，補充 38～40，標籤名 34，副標籤 28，數字 56（成對橫條圖的數字 40）；**下限 28px**。程式 B 檢查所有字級都在集合內 |
| 固定標記 | `@datasciocean`（角落） |

**對比度規則**（WCAG，一般文字至少 4.5）

| 文字色 | 底色 | 對比度 | 結論 |
|---|---|---|---|
| 深海 | 米色 | 10.2 | 補充文字 |
| 藍綠 | 米色 | 5.0 | 主標 |
| 米色 | 深海 | 10.2 | 深色面板上的文字 |
| 金色 | 深海 | 6.1 | 可用 |
| **金色** | **米色** | **1.7** | **禁止用於文字**，只能當色塊、底線、圖形 |
| 中藍綠 | 米色 | 3.2 | 只適合大字或圖形 |

米色底上要強調關鍵字，用金色螢光筆式的底色塊（`[[關鍵字]]` 標記），字維持深海色。

## 3. 版型（九種；`chart_bars` 另有成對橫條圖的變形）

| 版型 | 用在哪 | 底色與重點 |
|---|---|---|
| `cover` 封面 | 第 1 張 | 米色底；主標在畫面中段、副標在下；下段一條**海浪色帶**，顏色依系列，帶上放系列名稱；關鍵字用金色螢光筆標記；紋理只用在封面與帶走張 |
| `context` 脈絡 | 第 2 張 | 米色底；補充 140 字內，可加名詞對照表（`rows`，約 3 個詞放得下），圖上會出現的專有名詞在這一張或更早的張定義 |
| `text` 文字內容 | 機制、限制、評價等 | 米色底；主標在上、補充在下，位置每張固定；下方有一條鉛錘繩（裝飾，class `deco`） |
| `table` 對照表 | 兩欄對照（最多 4 列） | 米色底；主標在上，列高依文字斷行估算；右上角可有小標籤 `.chip`（金色細框）；補充可到約 4 行，表與圖依補充行數自動往下讓位；鍵欄寬可用 `key_w` 調，鍵可寫「主｜小字」；4 列以內 |
| `chart_bars` 橫條圖 | 錨點、證據 | 米色底，軸從 0 起，條長與數值成正比。**成對橫條圖**（`value2`）：同一批對象的兩個量（同單位）共用同一個 0 起點與比例尺，每組兩條，圖例在圖上方、名稱下可有一行小字；不用雙軸（2026-10-10 加入） |
| `chart_sounding` 測深圖 | 錨點、證據（Jev 系列的實作） | **深色海面面板**，見 §5 |
| `takeaway` 帶走 | 倒數第二張 | 深海底，金色字，只有一句話，字最大，適合截圖 |
| `recap` 前情回顧（2026-10-25，目前只有 sag 有模板） | 系列第 2 則以後的第 2 頁 | 米色底；前面各則與這一則各一列（第 N 則・前面介紹過／這一則 ＋ 標題 ＋ 一句細節），這一則深海色塊加金點；下半部系列路線（走過實心、這一則金色、後續空心）。內容來自 `series.md` 的 `summary` |
| `series_map` 系列地圖（獨立 post 為「延伸閱讀」） | 最後一張 | 米色底；列出同系列各則標題，目前這則用深海色塊加金色標記；底部導流行。系列檔成員有 `summary` 時（2026-10-25 起）每則「標題＋一句細節」，下半部加系列路線 |

**示意圖版型 `diagram`（2026-10-11 新增；除了最早的 jev-cascade，所有系列與獨立貼文風格都有模板）**：流程 `flow`、並列對比 `compare`、換掉什麼換成什麼 `pairs`、一個點 vs 一批點 `samples`、亂走 vs 小步走 `paths`、小步子與檢查旗 `epochs`、點陣 `dotgrid`、前後對比 `dumbbell`、區間條 `range`、漏斗 `funnel`、一個池子切成幾組 `batches`、從多降到少的曲線 `decay`（軸從 0 起）、三個停靠點 `stops`、幾組同時做再匯成一份 `fan`、兩條曲線高點重合 `peaks`、2×2 四格 `quad`、受保護區塊 `locked`（2026-10-12 加，skillopt 第 2 則用）、符號序列 `tokens`（2026-10-18 加，Decision Transformer 用：一列一步、每格一個符號，可蓋住一格；樣式 rtg／state／action／reward／mask）、蹺蹺板 `seesaw`（2026-10-22 加，Bradley-Terry 用：兩端各疊幾塊、梁向重的一邊傾斜，下面一條橫條的長度與方塊數比例成正比；純示意）、水面上下 `hidden`（同上：上面是看得到的結果、水面下是虛線框的「？」）、繞一圈 `cycle`（同上：三個節點 A→B→C→A，最後一條箭頭金色）。`pairs` 底下可加一條橫框（`outcomes[0]`，例如拿前面的例子驗算）。圖形全用 class `bg`（不進程式 B 的文字與圖形重疊檢查，排版由 `scripts/diagrams.py` 負責避開文字）、字級只用 {28, 34, 40, 56}、金色只給最重要的一處；框內文字與比例由程式 B 檢查。**不要每篇貼文都用同一種橫條圖**：文字下方空出來的區塊是「塗鴉牆」。

**系列標籤**：同一系列每則貼文的每一張，都要有系列標籤（封面放在海浪色帶上，其餘放左上角），文字必須與系列檔的 `name` 完全相同。獨立 post 沒有系列標籤。

**系列色**：從四層海浪深淺中選，相鄰系列不同色。獨立 post 用一個專屬色，不放系列名稱。

**主標位置**在所有版型（封面除外）都固定在同一處，讓讀者滑動時視線不用重找。

## 4. 依內容特徵選圖

### 4.1 帶數字的圖（先讀 `chart-thinking`）

| 內容特徵 | 圖的類型 | 元素上限 |
|---|---|---|
| 幾個數字的大小比較 | 橫條圖或測深圖，軸從 0 起 | 3～4 條（4 條時不用 subs，或用 `subs_inline`） |
| 同一批對象的兩個量一起看（同單位） | 成對橫條圖（`chart_bars` 加 `value2`） | 4 組 |
| 前後兩個值，加一條參考線 | 前後對比 `dumbbell`（軸從 0 起） | 2 點＋1 參考 |
| 一個量落在一個範圍 | 區間條 `range`（軸從 0 起） | 3 條 |
| 從多降到少（或反過來）的趨勢 | `decay`（軸從 0 起、高度與數值成正比） | 2 個端點 |
| 一個量被拆成幾部分 | 堆疊橫條（尚未實作；目前用三條橫條加名稱寫「其中」） | 3 段 |
| 隨某個變數的變化趨勢（有真實數據） | 折線圖（尚未實作） | 3 條線 |

### 4.2 機制與概念（2026-10-12 整理自 skillopt 三則；`diagram` 版型）

**選圖的方法：先問「這個機制在說一個什麼畫面」，再挑圖型。** 圖要讓讀者不讀補充也大致懂；純示意的圖標「示意」，不畫成實驗數據。

| 要講的機制 | 圖型 | 例子（哪一則） |
|---|---|---|
| 步驟、先後（3～5 步，可接結果分支或迴圈） | `flow` | 一步訓練怎麼走（skillopt 第 1 則） |
| A 與 B 對比、各有幾條特徵 | `compare`（可 `gone` 劃掉、`emph` 金條） | 訓練時 vs 上線後 |
| 「換掉什麼 → 換成什麼」、輸入對輸出的規則 | `pairs` | 四種做法各換成有紀律的版本；盲測結果三種 |
| 一個 vs 一批 | `samples`、`dotgrid`（點陣，實心／空心） | 單個隨機樣本 vs 一批；52 組測試 |
| 亂走 vs 小步走 | `paths` | 第二條：小步走 |
| 小步子、每輪結束的檢查旗 | `epochs` | 慢檢查 |
| 一個池子切成幾組 | `batches` | 切成 8 個一組 |
| 幾組同時做、再匯成一份 | `fan` | 各組同時診斷再彙整；新舊 Skill 同一份考卷 |
| 漏斗：很多篩成很少 | `funnel` | 提議的修改只收 1 到 4 次 |
| 一條軸上的幾個位置，選中間那個 | `stops` | 一組為什麼是 8 個；資料切成三份 |
| 一串依序排列的符號、其中一格被蓋住要猜 | `tokens` | Decision Transformer 的輸入序列與訓練時蓋住 action |
| 隔離、保護、誰能碰誰不能碰 | `locked`（文件裡一塊受保護區塊，一邊叉掉一邊通過） | 慢速更新的筆記（**人最喜歡的一張**） |
| 兩條線的高點落在同一處 | `peaks`（純示意） | 驗證分數與測試分數的高點重合 |
| 幾乘幾等於幾（資料量、模型數） | `equation`（A × B ＝ C，大數字；比點陣方陣更能說「怎麼算出來的」） | persona-aware-d2s 第 2 則：20 篇 × 4 種 persona ＝ 80 筆 |
| 2×2 的四種狀態 | `quad`（只有在格子的軸有卡上依據時才用；可加 `bars` 在格子上畫小投影片） | persona-aware-d2s 第 1 則：專家／非專家 × 長版／短版 |
| 看得到的結果 vs 看不到的隱藏量 | `hidden`（水面上是結果、水面下是虛線框的「？」） | Bradley-Terry：比賽結果看得見、實力值看不見 |
| 兩端不一樣重、傾斜多少就是機率 | `seesaw`（方塊數＝實力，橫條與方塊數成正比） | Bradley-Terry：實力 8 對 2，贏面八成 |
| A 比 B 好、B 比 C 好、C 比 A 好（循環） | `cycle`（金色箭頭是打破傳遞性的那一條） | Bradley-Terry 的傳遞性缺陷 |
| 一個東西同時連著好幾個東西、誰跟誰共用（事件↔實體、多對多） | `links`（左右兩排節點加連線；`hot` 把共用的那幾條畫成金色粗線） | SAG：一個事件綁五個實體；JOIN 串起共用實體的事件（2026-10-24 新增） |
| 幾跳才到答案（4 跳對 1 跳，每一跳等長） | `hops`（箭頭數＝`hops`，圖上的數字必須等於箭頭數，程式檢查） | SAG：二元圖譜跳 4 次、SAG 只跳 1 次（2026-10-24 新增） |
| 一個東西圈住好幾個東西（超邊、群組、一次綁定多個） | `bubble`（左邊一條只連兩點的邊，右邊金色大泡泡圈住 2～8 個項目；2026-10-24 新增） | SAG：一條超邊圈住五個實體 |
| 一路走偏、錯誤越滾越大 | `drift`（虛線是正確路線、實線一站比一站偏、終點打叉；純示意，圖註標「示意」；2026-10-24 新增） | SAG：向量檢索第一步偏一點，整條推理鏈跟著歪 |
| 系統架構：線下怎麼建索引、線上怎麼查（論文的架構圖） | `ingest`（上段淺色框：原始片段 → 一對一 → 多對多 → 資料庫；下段深色框：步驟由左到右，最後一步金色；2026-10-24 新增，人說比流程框更清楚） | SAG：線下不建圖，查詢那一瞬間才長出圖 |
| 一個系統由幾個元件分工、每個元件做什麼（2026-10-25） | `roles`（三列，每列一個圖示方塊：資料庫圓柱、向量點群、閃光；每列元件名＋角色＋做什麼） | SAG：SQL／向量／LLM 三個元件 |
| 精確比對 vs 語意相近（2026-10-25） | `embed`（左邊兩列比對：勾與叉；右邊向量空間：三個靠近的點圈在一起，遠處有不相關的點） | SAG：台積電＝TSMC？SQL 不行、向量可以 |
| 線上流程有兩條路進來、一路擴展、兩路決選（論文的線上檢索圖，2026-10-25） | `online`（起點 → 兩條路 → 第二步（循環箭頭）→ 兩路 → 結果） | SAG 第 2 則的線上三步 |
| 名額固定、上游來多少都只放行固定數量（2026-10-25） | `gate`（左邊一池散落的點、中間閘門上寫名額、右邊整齊排好的格子；同一則裡不要接著再放漏斗） | SAG：種子與前線實體各只留 50 個 |
| 兩路各挑幾個、合成一份（2026-10-25） | `concat`（兩排小文件匯成一排；不分來源，因為去重後組成不固定） | SAG：兩路各 5 個、合成 10 個 chunk |
| 逐一打分 vs 一起評估（2026-10-25） | `joint`（左：各自獨立的方塊各有一個分數記號；右：金色接起來、大括號圈住） | SAG：pointwise vs joint assessment |
| 兩條路各做一份、一條漏掉的由另一條補上（2026-10-25） | `rails`（兩條軌道各 6 格，A 的第 4 格是虛線空格、B 補上金格；合併後 6 格都滿） | SAG：路徑 A 漏接、路徑 B 保底 |
| 決策樹 | 尚未實作 | — |

**卡上有原圖可參考時**（`figures`，`make-social-post/references/anchor-writing-rules.md`「參考圖」）：不複製原圖，從上表挑一個圖型把原圖的**結構**重畫一次（流程、對照、表的數字），只畫這張引用的主張寫到的部分；原圖的評分點、圖示、品牌 logo 一律不帶。重畫的那張在 spec 寫 `fig_refs`，交重製圖審查者看。

### 4.3 用法

- **寧可大膽**（人，2026-10-12）：文字下方空出來的區塊是塗鴉牆；有隱喻的畫面（受保護區塊、漏斗、匯整）勝過一張表。可以新增圖型，不必先出樣張，但要附程式 B 檢查與回歸測試，並在交貼文時明講新增了哪些圖型。
- **同一則連續 3 張以上同圖型要換**（長得太像讀者會疲乏；編輯審查者每次都抓）。
- 圖上的文字靠 `word-break: keep-all`，**連續無標點的中文超過格子寬就會溢出**：見 `make-social-post/references/ig-carousel.md` §4「圖上格子的連續字數」。

共通規則：一張圖只傳達一個訊息；**圖要直接支撐主標**（`chart-thinking`）；**直接標示，不用圖例**（成對橫條圖是例外：兩個量共用名稱時，圖例貼在圖上方）；數字直接標在圖上並寫明比較對象；強調色只給一個元素；軸從 0 起，不截斷（若非截斷不可，要明確標示）。初期**不做比喻插圖**（照片或插畫），只做可以用程式產生的圖。不是每張都需要圖，說明為主的投影片用純文字版型。

要用「尚未實作」的圖型時，先在 `render.py`、`diagrams.py` 與模板加上該版型、補程式 B 的檢查與回歸測試，再用（人看貼文時一併審）。

## 5. 測深圖（`chart_sounding`，Jev 系列的實作，可當範例）

LLM 只輸出宣告式規格，模板負責所有計算：

```json
{ "layout": "chart_sounding", "unit": "倍",
  "bars": [ {"name": "官網頭條", "subs": ["最佳案例", "對比前沿模型"], "value": 193.6, "emphasize": true},
            {"name": "Every 實測", "subs": ["對比 Fable 5.1"], "value": 25} ] }
```

| 元素 | 規則 |
|---|---|
| 水面線 | 唯一的零點，所有繩子從它垂下 |
| 繩長 | 與數值嚴格成正比，由程式計算 |
| 鉛錘 | 小菱形，中心落在繩端 |
| 強調 | 只有一組（繩加鉛錘，金色，並有淡淡的光暈）；其餘用米色 |
| 刻度 | 在左右兩側邊緣，等距，每四格加長；**單位由程式依最大值挑選**（使相鄰刻度間距約 40～120px），圖例（「刻度每格 N 倍」）由程式產生 |
| 標籤 | 名稱與比較對象對齊繩的起點；數字貼在鉛錘右側；**數值很小的標籤改放水面線下方**，不得壓在線上 |
| 小數值 | 軸從 0 起，小值的繩可能只有十幾像素，這是誠實的視覺，不修，標籤放外側 |

不用深色面板的場合，改用 `chart_bars` 的米色底橫條圖。
